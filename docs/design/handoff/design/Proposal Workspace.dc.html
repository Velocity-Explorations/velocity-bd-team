Turn 9

From a call we like to a submitted proposal

Approved and done, 27 Oct 2026Built into the working prototype (01): Proposals, Start the draft, then Open workspace.Open the prototype

Every step of the proposal workspace, top to bottom in the order it runs, built on your answers: the dashboard guides each step, Claude does the work and saves Word files to Drive, and the owner approves on the dashboard. The example is the snapshot’s one pursued call. The plan is in Draft workflow plan.md.

Start

Pursue, then Start the draft on Proposals, To draft (or from the vote notice). The dialog shows the format read from the call and sets which steps need user approval, the owner and deadline, names the Drive folder, and shows the targets.

One step at a time

Each step: what it is for, what Claude prepared (the Word file in Drive and its key points), your call, and four actions. Only the open step asks anything of you.

User approval required, per proposal

Every step, or key gates only (go or no-go, the outline, ready to submit). With key gates only, the other steps run on and show as done with their files.

The clock

Targets worked back from the deadline with a day spare; a Behind warning on the step and in the digest; Slack when a step is ready; a daily digest at 08:00.

Formats first

SBIR or STTR technical volume, white paper, RFI response. The format sets the outline’s template and the page budget.

What the build needs

proposals and proposal_steps tables; a proposal agent that runs each step with the playbooks and writes Word files to Drive; approvals as server actions, like agent update requests.
