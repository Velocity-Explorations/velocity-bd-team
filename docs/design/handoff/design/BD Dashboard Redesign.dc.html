Velocity Theme redesign

Twenty-two artboards at 1440px (two at 1024px, 02 and 17), dark only, built from the 25 October 2026 snapshot and arranged in the four sections of the 26 October update. 01, the working prototype, is the default design; Turn 5 holds Home, the tabs, the new Proposals tabs and Profile settings. The handoff note for developers is 15, at the end.

01Home, Calls, Proposals and Automation: the default design, working prototypeOpens on Home (6a): the cards switch the list below, Needs review opens To review, agent update requests can be approved or rejected with a note, and Mark submitted moves a proposal on. Calls has no tabs or page title: six cards (Needs review, Claude yes, Claude maybe, Judges disagree, New this week, All calls) switch the table’s view and keep the portal, tag and open or closed filters. Proposals works the same way: Closing in 14 days, To draft (Draft proposal), Drafting (Open Drive folder, Mark submitted), Submitted and waiting (Record result) and Results (win rate by portal). Automation too: Agent update requests (Approve, Reject with a note), Decided requests, Scans, Scan problems and Judges agree. Open Review Queue Prototype on its own to try it at your window’s width.

Turn 7

Metric cards that line up

Today the number sits above the description, so a two-line description lifts it. All three options give the label, the number and the description fixed places that line up across the row, using CSS subgrid: each card spans the row’s tracks, so the tallest label or description sets that track for every card and nothing is cut off. The real labels and descriptions from Calls and Home are used, including the longest ones. The selected card keeps the ink border and accent bar.

Turn 6

Three ways to simplify Home

In 16, the top bar, the four cards and the tabs repeat each other. All three options drop the repeats: the Requests count lives only on Automation, Last scan and Judges agree move to a quiet footer line, and New this week folds into the Waiting for you line. They differ in how the lists are reached: 6a merges cards and tabs into one control, 6b merges the lists into one, 6c turns the short lists into alerts above the Top 10.

The other four open their list below: Due soon, Agent update requests, Proposals to draft, and Submitted and waiting. The Top 10 moves to the Monday brief, linked in the footer. The current structure, as built in 01

This block supersedes the 26 Oct block below wherever they differ (tabs, Proposals tabs, Home with tabs).

Structure

Four sections in the top bar: Home, Calls, Proposals, Automation; Past weekly briefs and Profile settings sit outside them. No tabs and no page titles: each section opens on a row of 7c view cards that switch the table below and keep the portal, tag and open or closed filters. Counts on Calls (waiting for you), Proposals (to draft) and Automation (requests).

Views and addresses

Calls: Needs review, Top 10, Due soon, Judges agree, Judges disagree, New this week, All calls. Proposals: Closing in 14 days, To draft, Drafting, Submitted and waiting, Results. Automation: Agent update requests, Decided requests, Scans, Scan problems, Judges agree. Address: #/calls?view=all&portal=NSTXL&tag=Space&state=open&sort=due&dir=asc&q=..., plus verdict, tier, filter_result and status; defaults left out (F10). In the build these become paths and query parameters: /calls?view=all.

All calls

Every scanned call. Title search applied on Enter, a Filter column (kept, rejected, pending; tier; reject reason), the call’s decision above the control, which reads Decide, Change or Add yours. A decision here becomes the call’s decision (newest wins); on the queue the first decision stays the call’s decision. Every vote is kept; the latest per person shows. Showing N of M with the judges’ agreement. The prototype shows 25 rows at a time for speed; the build keeps 200.

New writes

Draft proposal (drafting started, by and when, Drive folder), Mark submitted, Record result (won or lost), a call’s decision changed from All calls. Each is a server action; the first and third need ledger fields.

New components

View card row (the 7c card as a button with aria-pressed, or a link with an arrow); title search box; Filter cell; decision cell; brief board (content card whose label band is a stretched link); Profile settings rows, radio cards, checkbox chips; focus tooltip (shows title text on keyboard focus); loading and error states for the ledger.

Accessibility

Menus take focus on open, arrow keys move through items, Escape closes and focus returns to the trigger. Dialogs keep Tab inside and return focus on close. Hover text shows as a tooltip on keyboard focus. With reduced motion the card lift and transitions are off.

Defaults taken, to confirm

(1) Mark submitted and Record result write from Proposals, beyond V6. (2) The Drive folder is made on Draft proposal. (3) Drafting is a new state with its own fields. (4) All calls has its own Table settings. (5) Wording: Needs review, Agent update requests, “Log in (top right) before deciding”. (6) The card shadow and 3, 4 and 6px corners join the theme. (7) The Q12 explanation is not placed yet.

Not met

C8 (an out-of-date form writes nothing) needs the server; the prototype has one person at a time. The 26 Oct spec sections were not readable from GitHub, so this follows the chat brief. No sample data exists for a run still running after two hours, a log link, a Slack note or a single allowed person; the logic is there and shows when the data does.

Theme update: the card

7c is the default card, for the dashboard and the Velocity Theme

The theme files are in this project, ready to commit to docs/design/velocity-theme: velocity-theme/tokens.json (version 2), velocity-theme/card.css (the custom properties for tokens.css and the reference rules), velocity-theme/components/card/README.md, and the specimen Velocity Theme Card.

Use

Every metric card on every page: Home, Calls, Proposals and Automation. It replaces the flat StatTile and Card fill on app screens; slides may keep the flat card.

Layout

The card spans three rows of its row’s grid with grid-template-rows: subgrid, so the label band, the number and the description line up across the row. The tallest label or description sets that row for every card; nothing is clipped.

Label band

Chakra Petch 11px caps, padding 10px 14px, 1px rule below (--line-subtle #333333). Link cards put an arrow at the band’s right.

Number and description

Number Inter Tight 30px bold, padding 12px 14px 6px; yellow only for the count that needs you (Needs review, To draft, Agent update requests). Description Chakra Petch 12px #959595, padding 0 14px 14px.

--card-fill

linear-gradient(135deg, #2C2C2C 0%, #262626 45%, #212121 100%): lit from the top left.

--card-shadow

4px 6px 14px rgba(0,0,0,0.45), falling to the bottom right. The theme’s first shadow; cards only.

Selected

--card-fill-selected linear-gradient(135deg, #363636 0%, #2E2E2E 45%, #282828 100%), 2px ink border, band #383838 with a #555555 rule, a 3px accent bar along the bottom, shadow 4px 6px 16px rgba(0,0,0,0.55), aria-pressed.

Hover, pressed and focus

Every card. Hover: lift 2px (--card-lift), border #757575, shadow 6px 10px 22px rgba(0,0,0,0.55); a selected card keeps its ink border. Pressed: back to rest. Focus: the 2px accent outline, offset 2px. 140ms ease-out; with prefers-reduced-motion, no lift. Every card is a link or button, so static cards link to their detail (a judge’s score to Judges, a win rate to Results for that portal).
